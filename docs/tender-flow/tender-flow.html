Every person has their own login. The admin invites them on the Users page and picks their role. Engineers must have a phone number.

3. Tenders arrive

Admin

  • The admin uploads an Excel file (Tenders → Import from Excel). A Tender247 export is read as it is; files from other portals use a saved layout that says which column holds each detail. The import page picks the matching layout itself.
  • Every new tender lands in New. A tender already in the system is updated instead of added twice.
  • The import report lists what was added, updated and skipped, and why. The dashboard shows the date of the last upload.

4. Sorting new tenders

Admin

  • Add to Watchlist Watchlist for tenders worth keeping an eye on; Remove from Watchlist sends them back to New.
  • Reject Rejected for tenders the company will not bid on. A reason is required.
  • Several tenders can be ticked and handled at once.
  • Automatic: a tender still in New that nobody was assigned to is deleted 3 days after its deadline (the number of days is a client setting). Watchlist tenders are never deleted automatically.

5. Assigning an agent

Admin

  • The admin assigns the tender to an agent (or to themselves). A tender in New, Watchlist or Rejected moves to Assigned; assigning a rejected tender is how it is brought back.
  • The agent gets a bell notification, and sees the tender in their own lists from then on.
  • The agent can be changed while the bid is being worked on. Once the tender has a result, the agent is locked (see Rules reference).

6. Preparing the bid

Agent

  • The agent moves the tender to In progress and prepares the bid.
  • On the tender page they add the tender documents and make compliance PDFs: declaration letters printed on the letterhead of the chosen bidding company.
  • When ready, the agent sends it to Price review or Criteria review.

7. Review and decision

Admin

  • The tender waits for the admin. The admin either approves it to Ready to bid, or drops it to Not fit with a reason.

8. Submitting and the result

Agent (admins can make the same moves)

  • The agent submits the bid on the portal and moves the tender to Submitted.
  • If the buyer raises a query: Under query.
  • When the result is out:
    • Won: the award amount is required (and the award / PO number if known). Won tenders are moved one at a time for that reason.
    • Lost: a reason is required.

9. Deadlines

  • Reminders: the assigned person gets a bell notification when a tender still being prepared or reviewed is due in 2 days, and again on the deadline day. Each reminder is sent once per deadline; an extended deadline is reminded about again.
  • Deadline passed: a tender still being prepared or reviewed after its deadline day (in the client's own time zone) is moved to Not bidded automatically. Its previous stage is remembered.
  • Reopening: an admin can move a Not bidded tender back to any stage. After that, the deadline rule no longer applies to it.
  • Lists show the deadline in colour with the days left. After the win the deadline no longer matters, so it is shown as a plain date.

10. After the win: installation

Handing over

Admin

  • The admin moves the won tender to Assigned to engineer and fills in its Installation Report (Edit report on the tender page).
  • Order details: PO number and date, report date, customer, state office, department, address, contact person.
  • Consignees (delivery locations), each with its own engineer, contact details and call-aligned date.
  • Items under each consignee (Add item): the item name and configuration, how serial numbers are recorded, the number of units, and the warranty.
    • One serial number: printers, UPS, signal controllers…
    • Monitor and CPU serial numbers: desktop computers with a separate monitor.
    One consignee can mix both kinds.

The engineer's work

Engineer

  • The engineer sees only their own consignees: on their dashboard (My Assigned Installations), the tender page and the report page. The pages work on a phone; each unit is shown as a small card.
  • For each unit they fill in the serial number(s), installed (Yes / No / Pending), the installation date and remarks. They can fill up to the number of units the admin set; for more rows the admin adds them.
  • They set their status: Assigned → Site visit → Design → Installing → Completed.
  • They upload the signed installation certificate and site photos (PDF, JPG or PNG) to the consignee.
  • The admin gets a bell notification when an engineer marks a consignee Completed or uploads documents.
Rows left completely empty are not saved. They stay as rows to fill in on screen and in the PDF, but do not appear as installed units until someone fills them in.

The report PDF

  • Generate PDF prints the Hardware Installation Report for all consignees or one chosen consignee, with the bidding company's name and logo, and empty rows up to each item's number of units.
  • On the tender page the report is shown read only, with each consignee's documents.

11. Completing the tender

Admin

  • When installation is done, the admin opens the tender, checks the installation report, and moves it to Completed with a comment.
  • The Completed list shows Completed On and Completion Notes (that comment).
  • The Assigned to engineer and Completed lists only have a View button and no tick boxes: engineers are assigned in the report, and the move to Completed is made on the tender page.

12. After-sales: assets, warranty, tickets

Installed assets and warranty

  • Every filled unit appears on Installed assets, with its serial numbers, customer, consignee, engineer and warranty.
  • The warranty runs from the installation date (or the report date when none is given) for the item's warranty period.
  • Three boxes at the top count the follow-ups: Ending in 30 days, Ending in 31–90 days and Expired. Click one to list those units, then export them to Excel to call the customers about renewal (AMC).

Service tickets

  • From an installed unit, a service ticket is raised for a complaint, with its type and priority.
  • The ticket moves through New → With OEM → In progress → Resolved → Closed, and can be reopened.

14. What changed

DateChange
23 Nov 2026 First edition of this guide. It covers these recent improvements:
  • Watchlist tenders are no longer deleted automatically after their deadline; only unassigned tenders still in New are cleaned up.
  • Agent locked once a tender has a result (Won, Lost, Assigned to engineer, Completed, Not fit, Not bidded).
  • Assigned to engineer and Completed lists: View only; bid deadline shown as a plain date after the win.
  • Tender lists name the bid owner "Assigned Agent".
  • Bid deadline reminders (2 days before, and on the day).
  • Installation pages laid out for phones.
  • Warranty follow-up boxes on Installed assets; Excel exports follow the filters on screen.
  • Completed list: Completed On and Completion Notes.
  • Installation report items with one serial number or Monitor + CPU serials; engineers fill their own consignees; admin notifications.
